Forge Pipeline

A system is a network of subsystems. The agent walks that graph: it grounds each subsystem to real physics, sees which mechanism boundaries it may cross, solves the couplings as one fixed point, and optimizes the whole thing to a mission — tuning parameters and swapping mechanisms. Same machinery at every level of the recursion.
01

The pipeline

A mission and a system graph go in; a sized, buildable design comes out. The four agent stages are the process; the physics library is the reference they consult; the optimize↔solve loop is where the design actually moves.

02

What it operates on: the system graph

The pipeline's input isn't a parameter vector — it's a graph. Subsystems are nodes; the quantities they pass are the edges, and the edges are the physical couplings. A subsystem can decompose into children (recursion), and the solver treats the nesting transparently.

04

Two ways it optimizes

Naive — tune parameters

Hill-climb the design knobs (prop diameter, Kv, cells, arm length…) through the coupled solve toward the mission. Stays inside the current mechanism.

Physics-lensed — swap mechanisms

Try each alternative mechanism a subsystem could use, but only those within the radicality budget (rotor ↔ ducted-fan), re-solve, and keep the best. The design can change kind, not just size.

On the last run the agent tried both propulsion mechanisms and kept the rotor (2.09 kg) over the ducted fan (2.35 kg): both met the mission, but the duct's shroud mass beat its thrust gain for that mission. Raise the speed requirement and it flips — the choice is made on physics.

05

What holds, and what's scoped

foundation gate: PASS sanity: 20 / 20 0 dangling · 0 orphans recursion validated every mechanism node verified

The engine is complete and tested: the explicit graph reproduces the hi-fi solver, every subsystem grounds to a real law, the recursion aggregates correctly, and the physics-lensed swap picks the right mechanism. What remains is a tracked, integrity-guaranteed backlog — not loose ends:

  1. Broad library vocabulary canon — 30 independent agents named things ~15 ways for "thrust"; the engine handles it with a small function→quantity canon + context, but a full canonical pass is the production curation step.
  2. 22 physics-content corrections flagged by the library's verify pass — a curation queue; structural integrity is guaranteed regardless.
  3. Engagement objective — swap the capability floor (a_max/v_max ≥ target) for win-rate against a threat set, reconnecting to the interceptor mission.
  4. More subsystems / mechanisms — a wing (fixed-wing crossing), a fuel-cell energy mechanism, motor↔ESC↔rotor decomposition — each a new node on the same spine.
